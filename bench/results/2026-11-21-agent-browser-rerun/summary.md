## Interpretation Rules

- The direct arm keeps a cumulative harness conversation. The Browsemux arm sends compact current state and bounded action history.
- Both arms use the same browser executable, fixture tasks, model, snapshot limit, fresh-session policy, and deterministic success checks.
- Wall time includes browser open, the decision loop, and browser close.
- Browser commands count spawned `agent-browser` or BSK CLI processes. Model calls count successful JSON decision requests.
- A fixture benchmark controls page drift and bot walls. It does not establish universal performance on live sites.
- Provider-reported cost can change with routing, caching, and provider pricing. Keep the raw run JSON for audit.
